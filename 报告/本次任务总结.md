## 三、根本原因

`C:\Windows\SystemApps\LKG\` 目录下 6 个 LKG 系统应用包的文件被**整体清空**，
而系统部署数据库（StateRepository）仍认为它们已安装：

| 包名 | 用途 | 故障时文件数 |
| --- | --- | --- |
| `MicrosoftWindows.LKG.SpeechRuntime` | **语音识别引擎（Win+H 核心）** | 0 |
| `MicrosoftWindows.LKG.AccountsService` | 账户服务 | 0 |
| `MicrosoftWindows.LKG.DesktopSpotlight` | 聚焦/桌面 | 0 |
| `MicrosoftWindows.LKG.IrisService` | Windows AI | 0 |
| `MicrosoftWindows.LKG.RulesEngine` | 规则引擎 | 0 |
| `MicrosoftWindows.LKG.TwinSxS` | 组件服务 | 0 |

语音键入界面存在、引擎缺失，界面调用不到引擎，表现为无限转圈。

### 为什么常规手段查不出

1. **SFC 不校验 Appx/SystemApps 包内容**，因此报告「未找到完整性违规」。
2. 这些包对应的组件**未登记在 ComponentDetect 中**，DISM 亦无法感知。
3. 部署数据库中记录为「已安装」，与磁盘实际状态不一致。

## 八、经验与教训（可复用）

1. **SFC / DISM 存在盲区**：Appx 与 `SystemApps` 包内容不在 SFC 校验范围；
   未登记到 ComponentDetect 的组件，DISM 也感知不到。排查这类故障必须直接核对
   磁盘文件与部署数据库状态。
2. **`Add-AppxPackage -Register -DisableDevelopmentMode` 可能全局失效**：
   遇到 `0x80073CF9「部件清单没有位于程序包根目录中」`时，
   应立刻做一次「带参数 vs 不带参数」的对照实验，而不是反复重试。
3. **对照实验必须使用全新对象**：对已注册包重新注册属刷新操作，必然成功，
   不能作为有效对照。
4. **打包版本已登记时，散装注册会被 `0x80073CFB` 拒绝**，与版本号、
   强制参数均无关；Windows 内置包也不允许按用户卸载。
5. **`C:\ProgramData\Microsoft\Windows\AppRepository\<PackageFullName>.xml`
   就是 AppxManifest 原文**，可用于重建包或比对身份信息。
6. **系统镜像 `install.wim` 中的 `Windows\SystemApps\LKG\` 是系统应用包的原始来源**，
   是修复这类故障的关键素材。
7. **WUB（Windows Update Blocker）的残留不止策略键**：
   `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UpdatePolicy\GPCache` 中的缓存条目
   同样生效，其中缺少协议前缀的 `UpdateServiceUrlAlternate` 会导致
   `0x80072EE6（URL 协议无法识别）`，使 DISM 失去修复源。
8. **排查应逐层自我纠错**：本次过程中曾两次形成错误结论（System32 文件被删、
   路径大小写问题），均通过对照实验及时推翻，避免了误导性的修复操作。

## 十一、常用复查命令

```powershell
# 检查 LKG 包文件是否完整（应分别为 13/21/13/12/22/12）
Get-ChildItem 'C:\Windows\SystemApps\LKG' -Directory |
  ForEach-Object { "{0,-58} {1}" -f $_.Name,
    @(Get-ChildItem $_.FullName -Recurse -File -Force).Count }

# 检查语音相关包状态
Get-AppxPackage | Where-Object { $_.Name -match 'InpApp|Voiess|Speion|Speech\.' } |
  Format-Table Name, Version, Status

# 检查在线语音识别开关
(Get-ItemProperty 'HKCU:\Software\Microsoft\Speech_OneCore\Settings\PrivacyPolicy').HasAccepted

# 检查 Windows 更新是否可用
(New-Object -ComObject Microsoft.Update.Session).CreateUpdateSearcher().Search('IsInstalled=0').Updates |
  Select-Object -ExpandProperty Title

# 检查更新安装历史（结果码 0x4 为失败）
$s = (New-Object -ComObject Microsoft.Update.Session).CreateUpdateSearcher()
$s.QueryHistory(0, [Math]::Min(10, $s.GetTotalHistoryCount())) |
  Format-Table Date, @{n='Result';e={'0x{0:X8}' -f $_.ResultCode}}, Title

# 检查组件存储健康（需管理员）
DISM /Online /Cleanup-Image /CheckHealth
```
