# 语音输入故障 修复报告

- 机器：.（Windows 11 Enterprise 25H2，Build 26200.8655）
- 账户：.
- 报告时间：2026-09-26

---

## 一、故障现象

按 Win+H 呼出「语音键入」面板可以正常弹出，但**一直转圈、永远不出字**。
麦克风、网络、语言包在排查中均确认正常。

---

## 二、根本原因

`C:\Windows\SystemApps\LKG\` 目录下的 6 个系统应用包（LKG 系列）**文件被整体清空**，
但系统部署数据库（StateRepository）仍然认为这些包已安装。6 个包为：

| 包名 | 用途 | 故障时文件数 |
| --- | --- | --- |
| MicrosoftWindows.LKG.SpeechRuntime | 语音识别引擎（Win+H 核心） | 0 |
| MicrosoftWindows.LKG.AccountsService | 账户服务 | 0 |
| MicrosoftWindows.LKG.DesktopSpotlight | 聚焦/桌面 | 0 |
| MicrosoftWindows.LKG.IrisService | Windows AI | 0 |
| MicrosoftWindows.LKG.RulesEngine | 规则引擎 | 0 |
| MicrosoftWindows.LKG.TwinSxS | 组件服务 | 0 |

因此：语音键入界面（MicrosoftWindows.61869836.InpApp）在，但引擎缺失，
界面调不到引擎，表现为无限转圈。

### 为什么常规手段查不出、也修不好

1. SFC 不校验 SystemApps 内的 Appx 包内容，故报告「未找到完整性违规」。
2. 上述包对应的组件未登记在 ComponentDetect 中，DISM 也无法感知。
3. 网上教程通用的 `Add-AppxPackage -Register -DisableDevelopmentMode` 在本机
   属于**全局失效路径**：即使对一个全新的最小测试包也会报
   `0x80073CF9 部件清单没有位于程序包根目录中`。去掉该参数即成功。
4. 重新注册被规则拦截：`0x80073CFB 另一个用户已安装此应用的打包版本，
   未打包版本无法替换该版本`。尝试过 `-ForceUpdateFromAnyVersion`、提高版本号、
   `RegisterByFamilyName`、DISM 预置均被拒绝。
5. 该包为 Windows 内置包，不允许按用户卸载（错误 0x80073CF9 / 0x80070032）。
6. Windows 更新被 WUB（Windows Update Blocker）长期封锁，导致 DISM 没有修复源，
   报 `0x800f0915 在任何位置都找不到修复内容`。

---

## 三、已完成的修复动作

1. **提取原装引擎并还原**：挂载本机自备镜像
   `zh-cn_windows_11_business_editions_version_24h2_updated_march_2025_x64_dvd_55fb1ffa.iso`，
   再挂载其中的 `sources\install.wim`（索引 2 企业版，Build 26100.3476），
   取出带微软签名的 6 个 LKG 完整包，复制回 `C:\Windows\SystemApps\LKG\`。
   还原后文件数：13 / 21 / 13 / 12 / 22 / 12。
   其中语音引擎包含本地神经识别引擎、onnxruntime 推理库、回声消除模型等。

2. **解除账户上的「待移除」标记**：部署数据库中原先存在
   `Installed(pending removal)` 记录，已通过一次移除操作清除。

3. **开启在线语音识别**：写入
   `HKCU\Software\Microsoft\Speech_OneCore\Settings\PrivacyPolicy\HasAccepted = 1`。

4. **修复 Windows 更新**：清除 WUB 遗留的三处假 WSUS 配置
   （策略键、GPCache 缓存、服务状态）。其中 GPCache 中的
   `UpdateServiceUrlAlternate = .` 缺少协议前缀，
   是 `0x80072EE6（URL 协议无法识别）`的直接原因。

5. 重启系统，使上述变更生效。语音键入恢复正常（已实测可用）。

---

## 四、仍然存在的问题

1. **累积安全更新安装失败**：`2026-06 安全更新 KB5094126 (26200.8655)`
   更新历史结果码为 `0x00000004`（失败），且仍在待安装列表。
   原因是组件存储损坏（DISM 仍报告「可以修复组件存储」）。

2. **DISM 只能部分修复**：RestoreHealth 已从 Windows 更新下载约 3.1 GB
   修复载荷并执行修复，但仍以 `0x800f0915` 结束，说明部分组件缺少可用修复源。

---

## 五、后续建议

**推荐：执行一次「保留个人文件和应用」的修复安装（就地升级）**

1. 下载与当前系统版本一致的 Windows 11 25H2 官方 ISO（x64，简体中文）。
   注意：本机现有的 24H2 镜像 Build 26100.3476 低于系统 Build 26200.8655，
   Windows 安装程序会拒绝「保留文件和应用」的降级安装。
2. 在 Windows 中双击 ISO 挂载，运行其中的 `setup.exe`。
3. 选择「保留个人文件和应用」，按提示完成安装（约 40-60 分钟，需重启数次）。

该操作可一次性解决：LKG 系统包注册、组件存储损坏、更新安装失败、Appx 部署异常。
个人文件与已安装软件均会保留。

---

## 六、注意事项

1. **不要让 360 的「系统盘瘦身 / 大文件清理 / 系统急救」再次处理系统分区**，
   这极可能是本次故障的起因（它会删除系统应用包）。
2. 如需重新启用 WUB 关闭系统更新，建议**先完成上述修复安装**；
   否则将来修复系统仍会缺少文件源。
3. 已备份的配置还原文件：
   - `C:\hidisp\wu-policy-backup.reg`（Windows 更新策略）
   - `C:\hidisp\wu-gpcache-backup.reg`（更新策略缓存）
   - `C:\hidisp\recovered\`、`C:\hidisp\lkg-safety-backup\`（6 个 LKG 包原装文件）
4. 诊断日志位于 `C:\hidisp\*.txt`，确认无需后可删除。
