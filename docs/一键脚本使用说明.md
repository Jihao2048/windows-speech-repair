# Win11 语音键入 一键修复脚本 · 使用说明

主脚本：**`Fix-Win11VoiceTyping.ps1`**

一键诊断并自动修复「按 Win+H 面板弹出但一直转圈、永远不出字」的故障。
脚本按 8 个阶段顺序执行，每一步都会打印进度与结论，并在需要改动系统前征求确认。

---

## 快速开始

```powershell
# 1. 以管理员身份打开 PowerShell
#    开始菜单搜索 "PowerShell" -> 右键 -> 以管理员身份运行

# 2. 允许本次运行脚本（不改系统设置，仅当前会话）
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 3. 进入脚本目录并运行
cd "C:\hidisp\语音输入修复\脚本"
.\Fix-Win11VoiceTyping.ps1
```

脚本会自行检查管理员权限；若不足，会**自动弹出 UAC 提权重启**。

## 参数

| 参数 | 说明 |
| --- | --- |
| `-IsoPath <路径>` | 指定用于提取语音引擎的 Windows 11 ISO。省略则自动扫描各磁盘 |
| `-Auto` | **全自动模式**：跳过所有交互确认，直接执行修复。适合无人值守 |
| `-DiagnoseOnly` | **只诊断不修复**，不会改动任何东西。想先看结论时用这个 |
| `-SkipDism` | 跳过耗时的 DISM 组件存储修复阶段 |
| `-LogDir <路径>` | 自定义日志与备份目录，默认为脚本目录下 `SpeechFix_<时间戳>` |

### 常用组合

```powershell
# 只看诊断结论（不改任何东西，最安全）
.\Fix-Win11VoiceTyping.ps1 -DiagnoseOnly

# 全自动修复，指定镜像，跳过耗时的 DISM
.\Fix-Win11VoiceTyping.ps1 -Auto -IsoPath "F:\iso\win11_25h2.iso" -SkipDism

# 标准交互式修复
.\Fix-Win11VoiceTyping.ps1
```

> 注意：PowerShell 参数名不区分大小写，但**带参数时必须用英文连字符**，
> 例如 `-DiagnoseOnly` 不能写成 `-只诊断`。

## 执行流程（8 个阶段）

| 阶段 | 内容 | 是否改动系统 |
| --- | --- | --- |
| **0** 环境检查 | 管理员权限（不足则自动提权）、系统版本、创建日志目录、可选创建还原点 | 可选的还原点 |
| **1** 故障诊断 | 10 项检查：LKG 包完整性、引擎关键文件、在线语音识别、麦克风授权、语言能力、包注册状态、网络连通性、hosts/代理、界面组件、Windows 更新与 WUB 残留 | 否（只读） |
| **2** 基础修复 | 开启在线语音识别、修正麦克风授权、备份并清除 WUB 更新策略与缓存、恢复更新服务、清除 `pending removal` 登记 | 是（改前自动备份） |
| **3** 引擎提取 | 自动找 ISO -> 挂载 -> 挂载 install.wim -> 提取 6 个 LKG 包 -> 回填缺失文件并设置属主 | 是（改前自动备份） |
| **4** 尝试注册 | 依次尝试 3 种注册方式。**失败属正常**，实测不影响功能恢复 | 是（仅注册，无破坏性） |
| **5** 组件存储修复 | 先确认 Windows 更新可用，再执行 DISM ScanHealth / RestoreHealth / CheckHealth | 是 |
| **6** 重启输入进程 | 重启 `TextInputHost` | 否（进程级） |
| **7** 验证与报告 | 6 项验证 + 生成 `report.md` | 否（只读） |

**执行完毕后必须重启电脑**，然后按 Win+H 实测。

## 输出文件

全部输出到 `SpeechFix_<时间戳>\` 目录：

| 文件 | 内容 |
| --- | --- |
| `report.md` | 完整报告：诊断发现 + 全部执行日志 + 后续步骤 + 预防建议 |
| `diagnose.txt` | 诊断结论与 LKG 包文件数清单 |
| `dism_restorehealth.log` | DISM 修复的原始输出（若执行了阶段 5） |
| `extracted_LKG\` | 从 ISO 提取的原装 LKG 包（语音引擎等） |
| `before_restore_backup\` | 回填前的系统包目录备份 |
| `backup_*.reg` | 被删除的注册表策略备份（可 `reg import` 还原） |

### 还原方式

```powershell
# 还原被清除的 Windows 更新策略
reg import "SpeechFix_<时间戳>\backup_WindowsUpdate.reg"

# 还原系统应用包文件
Copy-Item "SpeechFix_<时间戳>\extracted_LKG\*" "C:\Windows\SystemApps\LKG\" -Recurse -Force
```

## 脚本能修什么、不能修什么

### 能自动修复

| 问题 | 修复方式 |
| --- | --- |
| 在线语音识别开关未开启 | 写入 `HasAccepted = 1` |
| 麦克风隐私授权被拒 | 设为 `Allow` |
| WUB 等工具封锁的 Windows 更新（含 `0x80072EE6`） | 备份并清除策略键与 GPCache 缓存，恢复服务 |
| **`SystemApps\LKG` 系统应用包被清空（含语音引擎）** | 从官方 ISO 提取原装包并回填 |
| 包的 `pending removal` 登记 | 通过一次移除操作清除标记 |
| 组件存储损坏 | DISM RestoreHealth（需 Windows 更新可用） |

### 不能修复，会给出提示

| 问题 | 说明 |
| --- | --- |
| 累积更新安装失败（结果码 `0x4`） | 组件存储严重损坏，需**就地修复安装** |
| `DISM /RestoreHealth` 报 `0x800f0915` | 部分组件缺少可用修复源，需就地修复安装 |
| 无法重新注册语音包（`0x80073CFB`） | Windows 内置包的正常规则，不影响功能恢复 |

**就地修复安装方法**：下载与当前系统版本一致（或更高）的 Windows 11 ISO →
双击挂载 → 运行根目录 `setup.exe` → 选择「保留个人文件和应用」。
个人文件与已安装软件均保留。

## 常见问题

**Q：脚本运行到一半报错怎么办？**
日志目录里的 `report.md` 会记录已完成的部分。把该文件内容贴出来即可定位。
所有改动在改前都有备份，可按上面的「还原方式」回滚。

**Q：阶段 4 注册失败是不是白做了？**
不是。实测中**仅还原文件 + 开启在线语音识别 + 重启，功能即可恢复**，
注册成功与否不是必要条件。请以「重启后按 Win+H 能否出字」为准。

**Q：没有 Windows 11 的 ISO 怎么办？**
从微软官网「下载 Windows 11 磁盘映像 (ISO)」免费获取。
注意：用于**提取文件**时，ISO 版本可以低于系统版本；
但用于**就地修复安装**时，ISO 版本必须 **≥** 系统版本。

**Q：脚本会收集我的个人信息吗？**
不会。所有输出仅保存在本地日志目录，不联网上传。
脚本也不会读取密码、凭据、产品密钥、文档内容等。
若要把日志分享给他人，建议先删除 `diagnose.txt` 中的系统版本行。

**Q：可以反复运行吗？**
可以。脚本是幂等的：已修复的项目会自动跳过，不会重复改动。

**Q：`-Auto` 模式会不会跳过必要的确认？**
会。`-Auto` 会跳过全部确认直接执行，包括删除注册表策略与回填系统文件。
**首次使用建议不加 `-Auto`**，先看清楚每一步再说。

## 安全提示

1. 脚本改动系统前均会自动备份到日志目录，但**仍建议先创建系统还原点**（阶段 0 会询问）。
2. 阶段 3 会向 `C:\Windows\SystemApps\LKG` 写入微软官方签名的原装文件，
   来源是你自己提供的 ISO，不含第三方内容。
3. 阶段 2 会删除 Windows 更新策略键——这是为了让 DISM 有修复源。
   若你确实需要保持更新关闭，请使用 `-SkipDism` 并在事后还原备份的 `.reg`。

## 预防再次发生

- **不要让第三方安全软件的「系统盘瘦身 / 大文件清理 / 系统急救」处理系统分区**——
  这是本类故障最常见的起因。
- 不要使用来源不明的系统精简 / debloat 脚本。
- 若用工具关闭了 Windows 更新，日后修复系统会缺少文件源，请谨慎。
- 定期检查更新历史：出现结果码 `0x4` 即为组件存储受损的信号。
